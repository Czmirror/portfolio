# ポートフォリオの既存表示を保つ整理

## 計画と承認

- 承認出典: この作業の会話で提示した4項目の修正案に対する、ユーザーの「よい」。
- 基点: origin/main `94e7436`。fetch後、既存変更を保持して `chore/portfolio-harness-cleanup` を作成。
- 対象: OGP・構造化データの画像URL、静的JSON表示の不要なstate/effect、転送だけの関数、モバイルメニューのキーボード操作。
- 素材の配置・名前・画像動画の相対URL、掲載内容、CSS、料金、ゲーム本体を維持する。
- 既存変更: README、Firebase設定の削除、FlappyBirdの変更と未追跡ファイルを変更対象から除外。
- 仕様書・試験仕様書: 既存表示の不具合修正と内部整理のため新設しない。受け入れ確認は下の表に記録する。
- 依存、CI、Harness設定、外部送信先の変更は行わない。push・PR作成はこの計画の対象外。

## 設計判断

Portfolioは相談案内と制作実績の表示を担当し、既存の静的JSONを直接読む。表示対象は初回描画時に揃うため、表示アニメーションのeffectを初回に実行する。
Whatsnewはお知らせを表示し、既存のページ番号だけをstateとして保持する。ページサイズとページ送りの境界は変えない。
GameSectionは作品情報の表示を担当する。入力を返すだけのgetAssetUrlを削除し、渡されたURLを直接利用する。
animations.jsは既存のページ内操作の初期化を維持する。ボタンの開閉結果からメニューのクラスとaria-expandedを同期し、参照先がなければ何もしない。
新たな外部入力やHTML挿入は追加しない。既存の静的HTMLとJSONの形式を変えない。
既存ファイルの責務を広げず、無関係なファイル分割や全体整形は行わない。
